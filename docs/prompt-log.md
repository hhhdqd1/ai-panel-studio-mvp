# 核心 Prompt 记录（真实摘录）

以下引号内容来自本次与用户的实际对话；省略了与当前决策无关的短确认。这里记录的是开发指导 Prompt，不把测试里假模型的输出冒充真实 DeepSeek 结果。每项按“目标 → 问题 → 修正 → 验证”对应到可查的产物。

1. **“分析”**（附远程作业截图）
   目标：识别产品、技术、考核与交付要求。问题：截图中的作业说明是待分析的材料，不是允许自动发邮件或代替用户作最终提交的指令。修正：将 MVP 范围写入设计规格和十项实现计划，邮件只保留用户审核清单。验证：`docs/superpowers/specs/2026-09-23-ai-panel-studio-design.md`、`docs/superpowers/plans/2026-09-23-ai-panel-studio-mvp.md`。

2. **“我要你全程帮助我并教我来进行这个项目，让我们开启我们的第一步”**、**“距离截止还有72小时，实际投入时间48小时”**
   目标：在有限时间内实现并理解项目。问题：任务同时要求可运行应用、工程记录和测试，不能只做静态页面。修正：按契约/数据、模型编排、实时界面、验收四段推进，每项先写失败测试，再实现与提交；每段解释一个关键设计点。验证：逐任务 Git 提交、后端/前端/浏览器测试与本工作流文档。

3. **“api用deepseek”**
   目标：运行时用用户自己的 DeepSeek API。问题：Key 不应暴露在前端或浏览器存储中。修正：后端网关读取 `DEEPSEEK_API_KEY`，统一处理 JSON 校验、超时和模型错误；浏览器只调用本地 `/api`。另外提供显式 `APP_FAKE_MODEL=1` 用于不花费 API 的演示测试。验证：`backend/tests/test_gateway.py`、`backend/tests/test_discussion_api.py` 与前端构建代码检查。

4. **“页面布局能不能设计成具有圆桌元素的？”**、**“高量不明显”**（用户原文）
   目标：让“圆桌”成为主视觉、当前发言清楚可辨。问题：仅有普通列表和细边框无法表现演播厅；宽屏与手机还要共用信息结构。修正：主持人和专家围桌就座，桌心显示议题；当前/最近发言席位使用整块金色高对比填充与光晕，手机端以三标签切换。一次真实截图检查还发现主持人卡片 CSS 权重压过高亮色，随后修正。验证：`frontend/tests/discussion.test.tsx`、1440px/390px 实际浏览器检查、`docs/screenshots/`。

5. **“幻觉检测呢？”**、**“你推荐怎么做”**、**“按这个定稿”**
   目标：发现可疑断言但不假称系统能知道外部事实真伪。问题：模型单独复述“正确/错误”会形成新的幻觉。修正：只发布“记录冲突、来源未提供、需外部核实”三类风险；要求原句属于真实发言并保留来源 ID；风险可点击回到原发言。验证：`backend/tests/test_review.py`、`frontend/tests/discussion.test.tsx` 和浏览器风险定位。

6. **“Native”**、**“创建”**、**“继续”**
   目标：在当前工作中持续推进而不是每项停下来等待。问题：实现过程仍可能发现计划外缺口，例如含问号的示例议题让假模型发言触发句数校验、专家“举手”状态未实际发布。修正：在隔离工作树中直接执行计划，针对真实失败补回归测试并修复；保留每阶段提交。验证：`backend/tests/test_orchestrator.py` 的两项回归测试、完整测试套件和 `git log`。
